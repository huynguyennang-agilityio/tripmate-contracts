# tripmate-contracts

What the TripMate repositories must agree on: the REST contract, the
realtime event schema, and the shared translations, with the checks that
guard them. This file holds only what is about this repository: setup,
commands, and conventions.

## What is here and who writes it

(api-design.md, section 6)

| File | Written by |
|------|------------|
| `openapi.json`, the REST contract | Generated by `tripmate-backend` (a pull request from its CI), never edited by hand |
| `events.schema.json`, the realtime messages and events | Written with the backend change that adds an event |
| `translations/en/<area>.json`, `translations/vi/<area>.json` | Anyone; every interface text, error code, and message key |
| `scripts/`, `tests/`, `.github/`, `.claude/` | The checks of this repository, their tests, CI, and the agent roles |

## Setup

- Node 24.2 or later, below 25 (`engines` in `package.json`; the check uses `import.meta.main`).
- `npm ci` installs every dependency from `package-lock.json`.

## Commands

| What | Command |
|------|---------|
| Tests of the checks | `npm test` (Vitest) |
| Translation check | `node scripts/check-translations.js [dir]` (`dir` defaults to `translations`) |
| Breaking-change check | `node scripts/check-breaking.js [file]` (`file` defaults to `openapi.json`; run in the git repository) |
| Next contract tag | `node scripts/contract-version.js [--base <rev>]` (prints the tag or nothing; creates none) |
| Install oasdiff | `scripts/install-oasdiff.sh [dir]` (Linux amd64; version and checksum are in the script) |

The checks exit 0 when there is no problem, and non-zero with every
problem printed otherwise. `npm test` needs oasdiff for the CT2 tests: set
`OASDIFF` to its binary, or have `oasdiff` on `PATH`.

## Translations

- `translations/<lang>/<area>.json`, with `<lang>` `en` or `vi`; one file per area, in both languages.
- A file is one flat JSON object of strings. Every key starts with its file's area and a dot, for example `auth.not_signed_in` in `translations/vi/auth.json`. A key in the file of another area fails the check.
- Messages are ICU message format, read with `@formatjs/icu-messageformat-parser` (the parser `next-intl` uses on Web) with its default options, so a plural or select without `other` is invalid.
- Both languages use the same arguments with the same types (plain, number, date, time, plural, select, selectordinal, tag), nested ones included. Plural and select branches may differ, because the languages have different plural forms.
- Inside a plural or selectordinal, `{n}` of its own argument counts as `#`, so en `{n, plural, other {{n} items}}` equals vi `{n, plural, other {# mục}}`; a different name (`{m}`) still counts as an argument.
- A file may start with a UTF-8 byte order mark. The files the operating system writes (`.DS_Store`, `Thumbs.db`, `desktop.ini`) are ignored in `translations/` and in the language folders.
- Known limit: a duplicate key inside one file is not detected (`JSON.parse` keeps the last).
- The check also fails on a file that is not valid JSON, a folder other than `en` and `vi`, and a file that is not `.json`.

## CI

`.github/workflows/ci.yml` runs on every pull request to `main` and on
every push to `main`. Each job is a check required on `main`; the check's
name is the job's name:

| Job | Runs |
|-----|------|
| `translations` | `npm ci`, installs oasdiff (the tests need it), `npm test`, and `node scripts/check-translations.js` |
| `breaking-change` | Pull requests only: installs oasdiff and runs `node scripts/check-breaking.js` |

Pushes to `main` also run the job `tag` (not required): it tags the merge
with `scripts/contract-version.js`, the only job with `contents: write`.
The contract pipeline is in the EPIC-11 spec,
[section 2.10](../tripmate-docs/docs/specs/epic-11/spec.md):

- A tag is `contracts-vX.Y.Z-draft.N` when any operation has `x-stub: true`, otherwise `contracts-vX.Y.Z`; the first tag is `0.1.0`.
- A draft is the next minor version and keeps its number, with `N` +1 on each merge, until its release.
- A release that adds an operation, a field, or an enum value, or changes `events.schema.json`, is the next minor version; any other change is the next patch version.
- Only a merge that changes `openapi.json`, `events.schema.json`, or a file under `translations/` is tagged. The changed files are those since the last tag.
- The breaking-change check runs `oasdiff breaking` against the last release tag and the latest draft newer than it; only error-level findings fail it, and with no tag yet it passes. Nothing checks `events.schema.json`.
- oasdiff is pinned by version and SHA-256 in `scripts/install-oasdiff.sh`; every job that needs it runs that script.

Third-party actions are pinned to a full commit SHA with the version in a
comment.

## Flow checks

`.github/workflows/flow.yml` runs the checks of development-flow.md,
section 2.3 (EPIC-11 spec, section 2.12), by calling the backend's reusable
`flow-checks.yml`; `.github/workflows/risk-gate.yml` (`pull_request_target`)
calls the backend's `risk-gate-check.yml`. Both are pinned to the same full
commit SHA of `tripmate-backend`; moving the pin is a normal pull request.
The checks required on `main` are `flow / failing-first`,
`flow / test-lock`, and `gate / risk-gate`. `flow / mutation` is skipped
here (no rule files) and `flow / risk-gate` is always skipped; never
require them.

- The flow checks come from the backend's `flowchecks` package.
  `failing-first` reads JavaScript tests (F15): `flow.yml` sets
  `node-version: "24"`, `test-file-pattern: tests/**/*.test.js`, and a
  `no-test-pattern` for Vitest's `No test found in suite` and `No test suite
  found in file` errors, and runs `npx vitest run <test file>` of each new
  test file at its test commit; it must fail. oasdiff is not installed there.
- `test-lock`: a commit without the trailer `Agent: test` must not change,
  skip, or delete a test of a test commit. For JavaScript the lock covers each
  test file as a whole: any change to it by a commit without the trailer breaks it.
- `risk-gate`: a High path changed and the pull request has no
  `human-approved` label. Only the product owner adds that label; Claude
  Code never does. A push removes it.
- The path list is `.github/risk-paths.toml`. High: `openapi.json`,
  `events.schema.json`, `.github/**`, `scripts/**`, every `CLAUDE.md`,
  `.claude/**`, `package.json`, `package-lock.json`, `.gitattributes`.
  Low: `translations/**`, `tests/**`, `tasks/**`, `README.md`,
  `.gitignore`. A path no rule names is High.

## How a card is built

Each card runs with four agents in `.claude/agents/`: `test-agent`,
`code-agent`, `test-check-agent`, and `diff-review-agent`
(development-flow.md, section 2.3). The tasks and their test cases are in
`tasks/<epic>.md`; the notes of review round 2 go in
`tasks/<epic>-notes/<card>.md`.

Each agent's model is set in its role file: `code-agent` runs on Sonnet;
`test-agent`, `test-check-agent`, and `diff-review-agent` run on Opus. Do
not override it when starting an agent.

- Branch `<type>/<ID>-<short-name>`, for example `chore/CT1-contracts-repository`; every commit message and pull request title starts with the ID.
- The test commit carries the trailer `Agent: test`, and tests live in `tests/<level>/<card>-<subject>.test.js`. No other commit changes, skips, or deletes them.
- Commit no secret and no `.env`: the repository is public.
